## 方法

- 签名按 Alpha 提取笔画，按比例缩小并二值化；嵌入真实笔画位图，不以名字或哈希替代。实际嵌入图和恢复图在本地展示。
- DCT：8×8 正交变换，修改亮度中频系数对的差值符号和最小间隔。
- FFT：64×64 正交实数傅里叶变换，修改非 DC、非 Nyquist 中频系数对的实部差值，逆变换得到实值亮度；每块分配多个比特。
- 两种算法均以独立本地随机密钥分配位置，重复嵌入后多数投票。提取需要密钥、原尺寸、签名尺寸与算法版本，不需要原始照片或原始签名。密钥及参数放在本地 sidecar。重复投票是冗余编码，实验不宣称具备完整纠错、安全认证或版权证明能力。
- 系数修改后的亮度差等量施加到 RGB，保持浮点色差；再四舍五入、限制到 8 位范围。统计裁切情况。完整 JPEG 保存后重新解码才计算提取误码率。
- 默认统一采用 JPEG quality=95、subsampling=0，复用项目方向与 ICC 处理，保持尺寸。实验 JPEG 仅保留方向、ICC、DPI，不作为保留完整拍摄元数据的正式成片。

## 画质和鲁棒性验证

- 每张输入分别生成无嵌入的重新编码基线，报告原始解码像素→基线、原始解码像素→水印输出、基线→水印输出。额外记录编码前的水印像素扰动。
- 画质指标为 RGB PSNR 和亮度 SSIM（7×7 均匀窗口、样本协方差、data_range=255，剔除窗口边界）；报告完整图指标，不用缩略图代替。指标不能代替视觉验收。
- 提取统计完整位图 BER 和笔画召回率，显示实际恢复图。无嵌入、错误密钥负例也报告 BER，不凭稀疏背景位正确率声称识别成功。
- 重压缩测试 Q90、Q75、Q50；缩放与裁剪分别标明是否提供已知几何信息。没有自动几何同步的算法不能把“已知尺寸/裁剪位置辅助恢复”算作独立抗缩放/裁剪能力。
- 全图、100% 局部和差异增强图提供一致取景，差异增强标明增益。交互页面仅引用同目录素材，不使用 CDN、远程脚本或上传服务。
- 记录算法耗时、文件大小和源素材前后哈希一致性；综合画质与提取表现选择组合示例，而非只选择 PSNR 最大者。

## 依赖和边界

实验工具使用 NumPy 和 Pillow；应用本身的依赖、配置、UI、打包和流水线保持现状。DCT 使用显式正交基，FFT 使用 NumPy 实数 FFT，SSIM 使用分块积分窗口计算，不增加 SciPy/scikit-image 到正式运行依赖。

本阶段不创建版本标签、Release 或 PR，不发布私人 demo。分支推送不触发现有仅对 main/PR 生效的 Windows CI；本地验证结果将明确记录。实验完成后等待用户画质验收和是否实现正式功能的决定。

参考：[Cornell JPEG 水印研究](https://www.cs.cornell.edu/info/people/mateev/Watermark/watermarkingJPEG.html)、[scikit-image 指标定义](https://scikit-image.org/docs/stable/api/skimage.metrics.html)。具体实现是本项目实验，不复述参考算法的鲁棒性结论。

## 单张实验使用

在已安装项目开发依赖的 Python 3.12 环境中运行。NumPy 来自现有 rawpy 依赖；本次验证版本为 NumPy 2.5.3、Pillow 12.3.0。脚本不需要 RAW 或联网。

```bash
PYTHONPATH=src .venv/bin/python scripts/frequency_watermark_demo.py embed \
  --source /path/to/local-photo.jpg --signature /path/to/local-signature.png \
  --output-dir demo-output/my-new-run --algorithm dct --strength 16

PYTHONPATH=src .venv/bin/python scripts/frequency_watermark_demo.py extract \
  --source demo-output/my-new-run/watermarked.jpg \
  --sidecar demo-output/my-new-run/watermarked.json \
  --output demo-output/my-new-run/independent-extraction.png
```

输出目录必须不存在，提取 PNG 也拒绝覆盖。`watermarked.json` 是含密钥与提取参数的本地 sidecar，须自行保管；它不含原始图像或签名比特。签名 PNG 展示真实嵌入图与保存后恢复图。`--restore-size` 仅用于已知原尺寸辅助提取，不能描述为自动抗几何变换。

F1 验证使用完全合成的 RGB 和签名，覆盖两种算法的 JPEG 往返、错误密钥/未嵌入负例、原尺寸限制、无效强度/容量拒绝、稀疏签名的笔画指标，以及 SSIM 与独立逐窗口公式的一致性和条带边界。CLI 验证输入不变、已有输出拒绝覆盖。实验模块在 `scripts/` 下，不进入应用 wheel。

## 批量画质对照

```bash
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/evaluate_frequency_watermark.py \
  --sources /path/to/photo1.jpg /path/to/photo2.jpg \
  --signature /path/to/local-signature.png \
  --output-dir demo-output/my-new-comparison --with-visible-watermark
```

`--with-visible-watermark` 使用仓库已有的两款本地字体和指定签名，调用现有可见水印渲染器。缺少字体时可省略该参数，仍可完成数字水印评估。每个新目录生成独立随机密钥，重复运行指标会因位置分配略有变化；一次运行内所有强度使用同一密钥，DCT/FFT 各自固定位置以公平比较强度。

输出 `index.html` 可直接在本地浏览器打开，也可仅绑定 `127.0.0.1` 运行静态服务器。页面包含滑动对照、全图概览、512×512 原尺寸局部、×16 差异增强、真实嵌入/恢复签名和各攻击条件。`sample-*/review-sheet.png` 是可离线查看的三列静态对照图。概览缩小采用 PNG，局部直接从重新打开的 JPG 截取并保存 PNG，避免为了展示额外引入 JPEG 损失。

程序自动从内部网格选择标准差最低、横向梯度最高、平均亮度最低的三个局部，分别用于平滑、细节、暗部观察。指标使用全图而非这三个局部。强度仅表示各自正交频域系数间隔，两种算法同一数值不代表同等扰动。

组合候选的预设选择规则：所有样图首次保存都精确恢复，并且 Q75/4:2:0 重压缩 BER 不超过 1%，在满足条件者中取平均基线 PSNR 最高者。该规则优先考虑画质与常规压缩，没有把辅助缩放恢复作为筛选条件，须另看对应结果。

## 2026-10-13 本地实测结论

两张本地样图分别为 6016×4016、5038×3363，采用同一随机密钥；嵌入签名为 128×77（9,856 位，笔画占 12.96%），每位重复 9 次。两种算法、三个强度共 12 组均在 Q95/4:4:4 首次导出后精确恢复全部签名位，且不向提取函数提供原照片或原签名。24 个未嵌入/错误密钥负例 BER 为 49.11%–50.59%，本次未出现负例匹配。尚未建立经大样本校准的检测阈值。

下表 PSNR/SSIM 均相对同参数重新编码基线，数值依次为样图 1 / 样图 2。Y-SSIM 使用本文所述 7×7 均匀窗口实现；不能与其他窗口、RGB 或缩略图 SSIM 混为同一口径。

| 方案 | PSNR / dB | Y-SSIM | 再压缩 Q75 BER |
| --- | --- | --- | --- |
| DCT 低（8） | 53.556 / 53.316 | 0.997523 / 0.995707 | 27.871% / 35.653% |
| DCT 中（16） | 49.966 / 49.067 | 0.992954 / 0.987782 | 0% / 0% |
| DCT 高（32） | 44.904 / 43.593 | 0.975606 / 0.957855 | 0% / 0% |
| FFT 低（10） | 46.719 / 47.973 | 0.988854 / 0.985419 | 0% / 0% |
| FFT 中（20） | 43.882 / 43.791 | 0.974090 / 0.961105 | 0% / 0% |
| FFT 高（40） | 39.519 / 38.547 | 0.927177 / 0.886737 | 0% / 0% |

重新编码基线本身相对原始解码像素 PSNR 为 46.125 / 49.950 dB。DCT 中档相对原始解码像素为 44.744 / 46.742 dB；所以“基线 PSNR 约 50 dB”仅指水印输出与同参数基线之间的差异，不能作为相对原片的最终画质值。

按预设规则，组合候选为 **DCT 中档**。当前全图及原尺寸局部预览中变化较轻，差异 ×16 图可定位到分块的周期扰动，视觉可接受程度待用户审查。DCT 中档文件大小相对基线为 6.064 / 5.890 MiB、2.596 / 2.426 MiB；嵌入算法耗时 1.485 / 0.686 秒，提取算法耗时 0.532 / 0.221 秒，均不含 JPEG 读写、色彩处理和评估。当前机器单次样图实验结果不能作为全机型性能保证。

鲁棒性揭示了不同侧重；数值仍为样图 1 / 样图 2：

| 方案 | Q50/4:2:0 BER | 缩到 50% 后按已知原尺寸辅助恢复 BER |
| --- | --- | --- |
| DCT 中档 | 37.388% / 48.843% | 42.248% / 46.956% |
| FFT 低档 | 1.684% / 1.573% | 1.015% / 0.994% |
| FFT 中档 | 0% / 0% | 0.010% / 0% |

因此，DCT 中档适合优先观察低画质扰动与 Q75 级压缩；若需求主要是缩图后找回签名，需要考虑 FFT 或继续研究其他方案，同时接受更大的像素扰动。FFT 中档样图 1 缩放后仍有 1 位误码，不能写成两张都精确恢复。所有方案在改变尺寸后**直接提取均拒绝**，没有自动同步。中心保留宽高各 90% 的裁剪，在已知裁剪偏移并放回原画布的辅助条件下，所有方案 BER 为 0.010%–0.142%；这些辅助结果不能证明未知裁剪后的可用性。

复用当前可见水印渲染器后，两张“可见水印 + DCT 中档”成片均独立提取到完全一致的签名，BER=0%；相对“仅可见水印”的 PSNR 为 49.920 / 49.053 dB，Y-SSIM 为 0.992960 / 0.987824。组合流程示例验证了预期插入位置，但没有接入正式流水线。

全部源照片、签名及两款字体的运行前后 SHA-256 一致。12 组评估及两张组合图共耗时约 255 秒，包含指标、攻击样图与预览生成。完整指标、裁切计数、哈希、密钥、来源路径、JPG 和恢复签名只在本地 `demo-output/`；浮点阶段超界的通道值以钳位方式处理，计数在本地报告中保留。

## 正式功能接入（2026-10-13 已授权）

用户已审查 JPG，并要求在水印栏增加 DCT/FFT 与三个档位，默认 DCT 中档；沿用本分支和逐节点提交推送。范围为 JPG 水印流程，NEF 仍仅支持坐标。本次不发布版本或构建新的 Windows 包。

- **N0：接入计划。** 确认设置、预览、预检和导出的共同参数边界，提交推送。
- **N1：运行服务。** 将已验证的频域核心移入 `services/`，显式声明 NumPy 依赖，固定算法版本、签名位图宽 128、9 次重复与六档系数间隔；增加签名资源限制、容量预检、分块取消及保存后提取核验。实验脚本继续通过同一核心复现。提交核心与回归测试并推送。
- **N2：设置与流程。** 水印栏提供附加开关、DCT/FFT 与低/中/高，默认开启 DCT 中档；水印设置窗口同步参数，个人默认与流程预设均保存。密钥自动生成并保存在本机个人配置，旧配置升级保留其他参数与备份，恢复项目布局默认不更换既有密钥。正式导出先合成可见水印、再嵌入数字水印、最后仅编码一次 JPEG；预览用同一配置。容量不足、签名不可用或导出后不能完整恢复时明确失败，不静默省略。提交接入与相关测试并推送。
- **N3：整体验证。** 本地静态、单元、GUI、元数据/事务流水线、自检与两张实际样图验证，检查 NumPy 包装依赖及私人素材边界；记录结果并推送。图片和 GUI 截图保存在本地忽略目录，不再提供网页形式。原生 Windows CI/验收是否执行据实际环境明确记录。

API 兼容：旧的底层 `WatermarkConfig` 和没有数字参数的显式工作流保持仅可见水印；新界面、个人默认以及经界面载入的旧预设补齐开启/DCT/中档与本地密钥。公开配置结构仅扩展参数，不改变已有字段含义。提取仍不提供自动几何同步，也不把签名嵌入称为密码学签名。
