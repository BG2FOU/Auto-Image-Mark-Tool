# 预检与处理性能优化验收

本轮保留 Python/PySide6 及锁定依赖，优化 ExifTool 进程复用、同一状态的元数据读取、局部水印合成、受限素材缓存和预检数据流。Pillow/FreeType/色彩转换本身已由原生库处理；本轮基准支持先减少重复工作，不引入新的 C/C++ 模块。

## 本地基准

基线源提交 `b647d25`；优化源提交 `a91e604`。同一 Linux 主机，固定种子生成 5038×3363 RGB JPEG，嵌入 sRGB/拍摄日期，使用自有合成字体和签名。每流程 3 张、3 轮，取中位数。每轮新 Python 进程，首张素材缓存为空，后续可复用；磁盘缓存未清空，不代表物理冷盘结果。正式串行/双线程测量顺序执行，未并行运行完整回归或 EXE 编译。主进程 RSS 不含 ExifTool 子进程，也不是各阶段瞬时峰值。Windows/真实混合照片速度需另行实测。

| 流程 | 预检：基线→优化（秒） | 处理：基线→优化（秒） | 主进程峰值：基线→优化（MiB） |
| --- | --- | --- | --- |
| 仅坐标 | 0.413→0.139（减少 66.3%） | 1.840→0.714（减少 61.2%） | 150.0→150.4 |
| 仅水印 | 4.121→1.708（减少 58.6%） | 8.753→5.532（减少 36.8%） | 360.8→281.3 |
| 坐标＋水印 | 4.573→1.614（减少 64.7%） | 10.553→6.281（减少 40.5%） | 361.2→281.3（减少 22.1%） |

每批 ExifTool 请求数（预检/处理）：仅坐标 3/6→3/6，进程启动改为会话复用；仅水印 6/18→3/9；组合 9/24→6/15。写后仍独立读回，不复用写入前记录。

复现：`python scripts/benchmark_pipeline.py --report build/performance/serial.json`；双线程原型加 `--workers 2`。原始 JSON/日志和生成素材仅保存在本地忽略目录。开发期间与回归/工具初始化重叠的探索测量不用于上表。

## 并行取舍

双线程仅作为基准原型，应用继续串行。仅水印处理 3.774 秒、组合 4.338 秒，比优化后串行减少约 31%；主进程峰值却从 281 MiB 增至 479 MiB（约增加 70%）。仅坐标 0.601 秒，收益约 16%。ExifTool 共享会话仍串行，记录的请求耗时含锁等待。小批合成测试未覆盖完整并行取消/关闭验收；当前内存取舍不适合直接启用，保留现有错误隔离和取消语义。

## 回归及 Windows 测试包门禁

本地非 RAW/非视觉回归 288 passed、2 Windows 专属 skipped；真实 NEF 回归 8 passed；19 类源码离线自检通过；Ruff/格式及 41 源文件 mypy 通过。四角水印与原整幅合成逐像素相等，Orientation 1–8、损坏 JPEG、ICC、资源替换、GPS/日期及原片保护均有覆盖。人工视觉验收未由这些测试替代。

Windows 字体占用修复 `c8c5072`、JPEG 预检优化 `a05fa6d` 和基准原型 `a91e604` 的原生 Windows 源码 CI 均成功。候选测试包版本为 `0.4.0rc5`，尚未发布；公开下载仍为既有 rc.4。

测试包从已提交源码的干净快照本地构建，使用 Python 3.12.3、哈希锁定 Windows wheels、PyInstaller 6.22.3 和 ExifTool 13.59。只复制公共工具与许可缓存，不复制私人照片、字体、签名或 demo。构建来源、文件哈希和实际冻结检查结果完成后追加至验收记录；Wine 兼容环境检查不能替代用户原生 Windows 验收。

收到 EXE 后，请以照片副本分别测试仅坐标、仅水印、组合流程，记录张数及预检/处理时间；检查方向、颜色、水印位置、GPS/拍摄日期，测试中文路径、替换字体/签名、取消和重新运行。保持独立输出目录，使用已有本地字体/签名。只有用户确认测试通过后才创建标签、执行正式远端构建与 Release。
