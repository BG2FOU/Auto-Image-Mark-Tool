# Auto Image Mark Tool v0.5.1

减少开始处理前的等待，并优化 JPG 水印与 NEF 坐标副本处理。用户已于 2026-10-28 确认 `0.5.1rc1` Windows 测试包通过，正式版沿用该候选的处理逻辑。

- 默认“快速检查”：保留参数、资源、文件头与输出冲突检查，将完整解码、ICC 试验、试渲染和 NEF 基线校验放到逐张实际处理；可切换“完整检查”提前排查整批文件。快速模式可能在前面的照片已完成后才发现后续坏图，失败按行报告。
- NEF 完整指纹从三次 ExifTool 请求合并为两次，在固定 ExifTool 内对全部预览计算完整 SHA256，减少大块预览传输；保留 RAW、预览、非 GPS 元数据和写后 GPS 核验，不使用抽样哈希。
- 合并重复读回与校验，减少大图和 DCT/FFT 的内存复制；预览复用有界缓存，符合内存预算的 JPG 批次最多并行两张。原片变化检查、最终频域水印恢复、失败隔离和不覆盖成品仍有效。
- Linux 同机五轮配对的三张约 17MP 合成 JPG：自动预检中位数 `1.902→0.109s`，水印整批 `7.094→5.403s`；两份授权 NEF 样片整批 `2.246→1.545s`。这些是指定样本的测量，实际收益取决于照片、磁盘与系统。

Windows x64 提供单文件 EXE 和目录 ZIP，Ubuntu 24.04 / Linux amd64 提供 DEB；两平台执行 28 类冻结自检，并提供 SHA256SUMS.txt、BUILD_INFO.json、第三方声明和许可归档。公开包不含私人照片、字体、签名或个人配置。EXE 未签名；NEF 显影及水印继续暂缓。构建及公开下载证据见 [验收记录](https://github.com/BG2FOU/Auto-Image-Mark-Tool/blob/main/docs/acceptance.md)，测量范围见 [性能实施记录](https://github.com/BG2FOU/Auto-Image-Mark-Tool/blob/main/docs/performance-implementation.md)。
